migration starts.

## 2. Guard behaviour (implemented)

| Code | Condition | Fail-closed |
|---|---|---|
| **F1_CANARY** | `Intl` missing, or any canary pair not ordered the ICU way (`"a_" < "a0"`; the F-7 critical pair; a same-vs-wider prefix pair) | exit 1 |
| **F2_ORDER** | effective order (`readdir` → `sort((a,b)=>a.localeCompare(b))`, the CLI's own comparator) ≠ baseline order | exit 1 |
| **F3_UNEXPECTED_MIGRATION** | a migration directory on disk is not in the baseline | exit 1 |
| **F4_MISSING_MIGRATION** | a baseline directory is missing on disk | exit 1 |
| **F5_CHECKSUM** | any `migration.sql` sha256 ≠ baseline (comments, blank lines and a single newline included) | exit 1 |
| **F6_BASELINE** | baseline missing / unparseable / unknown `schemaVersion` / malformed shape | exit 1 |
| **F7_NO_MIGRATIONS** | migrations directory missing/unreadable, or zero migration directories | exit 1 |
| **F8_PRISMA_VERSION** | installed Prisma ≠ `baseline.prismaVersion`, or version undeterminable | exit 1 |

**Read-only by construction.** The guard imports only `node:crypto`, `node:fs`, `node:path`, `node:url` (asserted by
test **T12b**), never references a DB driver or a URL, and writes no file unless `--update` is passed.

## 5. Compatibility impact

| | Fresh DB | Existing DB (all 22 applied) |
|---|---|---|
| `db:preflight` PASS | `db:deploy` proceeds → `migrate deploy` applies 22/22 in the audited order | `migrate deploy` finds nothing pending → no-op; **no DDL, no data change**; the known pre-fix 4-row checksum delta is untouched |
| `db:preflight` FAIL | deploy **never starts** → no partial schema, no failed `_prisma_migrations` row | blocks a no-op deploy (fail-closed by design); remedy is a compliant runtime, **never** a bypass, `migrate resolve`, or a ledger write |

The guard is static, so its verdict is independent of database state; it never reads or writes
`_prisma_migrations`. Non-migration consumers (app, worker, seed, tests) are unaffected.

## 6. Remaining risks

| ID | Risk | Severity | Mitigation |
|---|---|---|---|
| R-1 | Manual `npx prisma migrate deploy` bypasses the guard | Medium | Documented in `README.md`; the approved path is `db:deploy`. A future phase could add a wrapper/CI gate. |
| R-2 | Guard replicas the CLI comparator (Prisma's loader is not exported) | Medium | `prismaVersion` is frozen and **F8 hard-fails** on any change, forcing re-verification — the failure mode is fail-closed, not silent. |
| R-3 | Baseline becomes stale when a migration is added | Medium | `--update` + review; a stale baseline fails closed with an explicit remedy message. |
| R-4 | No CI exists, so the gate runs only where the operator/scripts invoke it | Medium | README documents it; the guard is committable (in `tools/`, which is **not** gitignored — unlike `scripts/`). |
| R-5 | T9/T10 use preload simulation, not a real small-/no-ICU Node binary | Low | The primitive (`localeCompare`) is exactly what is shadowed; a real binary would add no information. Recorded as a limitation. |
| R-6 | Guard cannot repair a drifted runtime, only refuse | Low | Intended (fail-closed by design). |
